## 主な知見

- **座標系・ライブラリ仕様の罠に弱い**: deltaTimeの二重補正（`*60`）、ローカル/ワールド座標の混同、`Raycaster.camera` の仕様、二重宣言の混入など、3D特有の落とし穴をほぼ全部踏んだ
- **エラーメッセージがあれば確実に直す**。曖昧な症状（「画面が一色」）だけでは3ラウンド空振りした
- **デバッグログ方式が転機**: 「推測修正をやめてログを仕込め、出力は返す」ループに切り替えた修正4以降、原因特定が一気に進んだ。ログに何を出すべきかの設計自体は的確だった
- 修正で別の場所を壊す事故が2回（構文エラー混入、左右反転の再発）
- ユーザーのグローバルCLAUDE.md（計画先行・承認ルール）をopencode経由で読み込み、忠実に承認待ちで停止する挙動を複数回確認（指示遵守性は高い）
- `node --check` はV8遅延パースの関係でブロック内の二重宣言を見逃す。モジュール実ロードでの構文確認が必要
